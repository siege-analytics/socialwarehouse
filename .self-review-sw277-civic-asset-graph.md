## Peer review (mechanics, correctness, craft floor)

**Pattern fidelity.** `socialwarehouse/orchestration/assets/civic.py` follows the identical structure established in `geo.py`:
- Bronze: 3 `SourceAsset` declarations (districts, schools, EDGE) with `AssetKey(["warehouse", "bronze", ...])` keys and `group_name="bronze"`. Matches `addresses_raw` pattern.
- Silver: 3 `delta_table_asset()` calls with `(context, spark)` compute functions, each reading bronze via `get_table_path()` and writing to silver. Matches `addresses_typed` pattern.
- PostGIS: 3 `postgis_materialization_asset()` calls targeting the three Django models. Matches `geo_address_postgis` pattern.
- `all_assets` list exported for definitions discovery.

**Asset key verification.**
- `delta_table_asset(layer="silver", table="nces_districts_typed")` → `AssetKey(["warehouse", "silver", "nces_districts_typed"])`. Matches convention.
- `postgis_materialization_asset(target_django_app_label="sw_civic", target_django_model_name="NCESDistrictAggregate")` → `AssetKey(["postgis", "sw_civic", "ncesdistrictaggregate"])`. App label verified from `civic/apps.py` line 7: `label = "sw_civic"`.

**Dep wiring.** Each silver asset depends on its bronze counterpart; each PostGIS asset depends on its silver source. No cross-chain deps (districts↔schools↔EDGE are independent chains). Verified in test assertions.

**Registration.** `definitions.py` updated: `assets=[*geo.all_assets, *civic.all_assets]`. `assets/__init__.py` updated: imports `civic` alongside `geo`.

**Compute functions.** Silver compute functions are placeholder pass-throughs (`typed_df = bronze_df`) matching the geo pattern — the typing transforms are follow-on work. PostGIS shape functions are also pass-throughs, matching `_shape_for_address_model` in geo.py.

**No gold layer.** Design decision: the three NCES data sources map 1:1 to Django models with no cross-source enrichment join needed. Gold layer can be added as follow-on if district+EDGE joined view is needed.

**Tests.** `tests/orchestration/test_civic_assets.py` verifies asset key topology (keys + dependency_keys) for all 9 assets without executing compute functions (which need Spark). Uses `pytest.importorskip("dagster")` matching existing test convention.

**Syntax verification.** All 4 modified/new files pass `py_compile`. Cannot run pytest in this environment (Django/Dagster not installed) but test file structure matches existing `test_factories.py` convention.
