## Hostile review

Hostile-review-artifact: .hostile-review-sw369-narrative-event-exposure-class.md

An independent agent (no access to this session's reasoning, only the diff and the live repo) ran an adversarial review and returned verdict **FAIL** with 1 BLOCKER, 1 MAJOR, 4 MINOR findings. Full report at the path above. Resolution:

- **[BLOCKER, FIXED]** `sourcing_note` whitespace-only bypass: the DB `CheckConstraint` only rejected the literal empty string, while `clean()` also rejected whitespace-only -- but `clean()` is never called by `.objects.create()`/`.save()`, so `sourcing_note="   "` slipped through the real write path silently. Fixed by changing `ck_evpart_sourcing_note_required` to use `sourcing_note__regex=r"\S"` (compiles to Postgres `~` regex match requiring at least one non-whitespace character), closing the gap at the load-bearing DB layer instead of relying on the weaker literal-empty-string check. Added `test_incidental_private_with_whitespace_only_sourcing_note_rejected_on_real_write_path` to prove the fix against the actual `.objects.create()` path, not just `.clean()` called directly.
- **[MAJOR, FIXED]** `duration_mode="bounded"` accepted both `window_pre_days`/`window_post_days` NULL -- a "bounded" event with no actual bound. Fixed: `ck_evnarr_duration_mode_fields` now additionally requires at least one window field non-null in bounded mode (kept "independently settable" per the ticket -- either field alone is sufficient, just not neither); `clean()` updated to match. Added `test_bounded_mode_with_no_window_fields_rejected_by_db_constraint` and `test_bounded_mode_with_only_post_window_set_succeeds`. Fixed the pre-existing `test_access_via_event` which had incidentally (and un-assertedly) relied on the old permissive behavior.
- **[MINOR, RESOLVED-NOT-A-BUG]** `CreateModel`/`AddField` split for `NarrativeEvent.event`: reproduced this exact split from a from-scratch `makemigrations` regeneration in this session (before any hand-editing) -- confirmed to be Django's native autodetector output when multiple model/field changes land in one migration, not an artifact of stripping the unrelated ops.
- **[MINOR, FIXED]** Inconsistent `ValidationError` shape in `NarrativeEvent.clean()` (dict-keyed vs. bare string) -- both branches now raise dict-keyed `ValidationError`s attached to the relevant field name(s).
- **[MINOR, NOTED, NOT FIXED]** No enforcement that `Event.event_type` matches the attached subtype -- confirmed pre-existing across all four subtypes (`CorporateEvent`/`SpatioTemporalEvent`/`ElectoralEvent`/`NarrativeEvent`), not a regression introduced here. Noted as a follow-up in the PR body rather than fixed in this PR (fixing it would mean touching all four subtypes uniformly, which is bigger scope than #369).
- **[MINOR, FIXED]** Test coverage gaps: added the UPDATE-path test (`test_update_to_incidental_private_without_sourcing_note_rejected_by_db_constraint`, confirming the constraint re-validates on `UPDATE` not just `INSERT`) plus the whitespace-real-write-path and bounded-no-window tests above. The `Event.event_type`/subtype-mismatch gap is left untested, matching the "noted, not fixed" resolution above.

### CodeRabbit follow-up (PR #371, post-push)

CodeRabbit's automated review on PR #371 posted 3 findings:

- **[FIXED]** The Role declarations section above previously self-identified each role's nature using the vendor-model term this workspace's no-AI-attribution policy prohibits in committed artifacts. Reworded to role-neutral phrasing (implementer / self-review pass / independent adversarial pass); no change to the section's meaning, just the phrasing.
- **[FIXED]** `EventParticipant.exposure_class`'s `ck_evpart_sourcing_note_required` constraint was permissive-by-NOT: any `exposure_class` value outside the declared choices (e.g. `"banana"`) satisfied `~Q(exposure_class="incidental_private")` and silently skipped the `sourcing_note` check, even though Django's `choices=` already blocked such values at the ORM/admin layer. Added `ck_evpart_exposure_class_valid`, a new `CheckConstraint` rejecting any `exposure_class` not in `{public_actor, incidental_private}`, ahead of the existing `ck_evpart_sourcing_note_required` in `Meta.constraints`. Migration `0003_narrative_event_exposure_class.py` updated to include the new `AddConstraint` operation.
- **[ALREADY DEFERRED, NOT RE-FIXED]** `NarrativeEvent.event`/`Event.event_type` mismatch: this is the same pre-existing, all-four-subtypes gap already identified and deferred above ("No enforcement that `Event.event_type` matches the attached subtype"). CodeRabbit's independent discovery validates the finding rather than requiring a new fix in this PR.
