- `EventLink` is designed as a junction/bridge row between two `Event`s (plain `models.Model`, direct `sourcing_note` field), matching `EventParticipant`'s established pattern in this codebase rather than `Event`'s heavier polymorphic-Attestation-linked pattern -- `EventLink`, like `EventParticipant`, is structurally a relationship row, not a first-class entity.
- `NarrativeEvent`'s docstring previously described #370 narrowly as "supersession linkage (one event closing another's regime)" -- narrower than the ticket's actual `precedes`/`relates_to` scope. Corrected in this PR (one paragraph) so the docstring accurately references `EventLink` instead.
- `sourcing_note` is **unconditionally** required for every `EventLink` (unlike `EventParticipant.sourcing_note`, which is only required for `incidental_private`) -- an edge with no stated justification carries no more evidentiary weight than a coincidental time-window overlap, which defeats the entire purpose of the ticket.
- Two lessons from SW#369/PR#371 were applied proactively rather than waiting for a review to catch them: (1) the `sourcing_note` DB constraint uses `sourcing_note__regex=r"\S"` from the first draft, not a literal-empty-string check (the exact whitespace-bypass bug SW#369's hostile review found the hard way); (2) `edge_type` gets its own DB-level enum `CheckConstraint` from the first draft (the exact gap CodeRabbit found in SW#369's PR#371 follow-up).
